# 技术架构

## 运行与构建

- `miniprogram/` 是小程序根目录，微信开发者工具使用原生 TypeScript 编译插件。`package.json` 提供静态类型检查和衣橱/人体/试衣/穿搭测试。
- `pages/` 只处理界面状态与导航；`components/` 承载可复用展示；`models/` 定义业务契约；`config/` 管理分类、主题和可调整参数。
- `services/` 承载衣物、身材、试衣会话、穿搭规则与图片操作；`repositories/` 封装衣物、身材和穿搭读写。`rendering/` 实现人体计算、衣物布局、图片缓存和 Canvas 绘制。试衣图层与范围集中在 `config/try-on.ts`。

## 数据流

页面 → 服务 → Repository 接口 → 微信本地存储/用户文件。图片文件与结构化记录分开管理。普通穿搭引用衣物 ID，保存模特调整参数和可选的独立画布排列，不复制照片或身材。

衣物记录使用带 `version: 1` 的本地快照。读取到异常结构时拒绝继续写入，以免覆盖原数据。照片复制进 `wx.env.USER_DATA_PATH` 后才写入记录；记录保存失败时清理刚复制的文件。

## 试衣坐标设计

身材输入生成逻辑人体及肩部、胸、腰、臀锚点，计算不修改输入。`body-model.ts` 输出以 cm 为单位的路径；`canvas-fit.ts` 使用统一比例 `min(可用宽/逻辑宽, 可用高/逻辑高)` 并居中；`draw-body.ts` 将描边计入边界，按设备像素比绘制。`body-preview` 组件在属性、页面显示和尺寸变化时重新测量。

第四阶段贴图已共用人体变换：画布统一适配之后，再按每件衣物的逻辑偏移、绕图片中心旋转和等比缩放绘制。原图模式按肩、腰、臀锚点推算且保留图片宽高比；2026-10-13 增加分区模式，先按校准变形再应用整件衣物的调整。画布拖动的 CSS 像素位移除以统一适配比例得到逻辑 cm 位移，避免设备像素比干扰。

`TryOnSession` 维护运行期间的衣物 ID、图层、调整参数及当前选择。同层替换；连体装与上/下装双向互斥；外套保持。默认渲染顺序为下装→上装/连体装→外套，长按置顶后按可选 zIndex 绘制/命中，模特选中框最后绘制。页面重新显示时核对衣橱：新草稿移除失效衣物；编辑已保存穿搭时将失效引用移至不可用位置列表并原样保留，包括手动层序。读取失败保留草稿。

`CanvasImageCache` 为每个 Canvas 维护图片对象，移除不用的缓存；贴图读取失败时尝试展示照片并提示，全部失败时跳过该件，不影响其他衣物。组件使用递增版本拒绝迟到的查询/图片结果，卸载后不再更新，读取超时为 10 秒。

绘制不回写原始身材数据。第一版围度只推算示意宽度；异常大的正数可保存，但推算比例设限以防溢出。

男女陈列模特现使用连续曲线和本地渐变，选填肩宽/上身长/内侧腿长驱动肩、腰、裆点，女模下胸围细化胸廓。表单即时预览未填项使用分性别示例，保存时不写入估算值。模板内部 ID 和身材 version 1 不变。

`image-content.ts` 只分析 alpha，不删除白色或照片背景；`CanvasImageCache` 用原生离屏 Canvas 将最长边缩采样至 384 像素分析并按图片缓存，读取不支持时保留原图。裁切来源和主体宽度参与默认定位；原图绘制、选框与命中共用内容矩形，源文件不变。分区模式另外使用剪影行/校准与人体锚点生成网格，选框用网格边界，命中用三角形；离屏缓存加明暗，人体手颈局部作为前景，不作真实布料模拟。模块说明见 `docs/memory/architecture.md`。

## 穿搭保存与引用

`LocalOutfitRepository` 使用独立版本化快照；`OutfitService` 校验名称、图层唯一/互斥、参数范围及衣物引用。新增穿搭必须全部引用有效衣物；更新可以原样保留已有失效引用，不能伪造失效引用或修改其参数。`resolveOutfitItems` 为列表、详情和试衣提供有效衣物与缺失/换层提示。

`TryOnSession` 保存编辑来源 ID/版本、名称及初始内容签名，判断未保存修改。载入会恢复逻辑参数；保存成功后才更新基线，失败保留旧记录及草稿。每次修改增加 `revision`，保存/改名/删除/恢复均检查版本，阻止旧页面覆盖新内容。另存不改动来源记录。

穿搭删除为单快照中的 `deletedAt` 标记，恢复移除此标记，不删除图片或衣物。活动卡片删除用 catchtap 阻止进入详情，确认/版本保护，日历保留。删除衣物前统计活动与回收站穿搭引用并提示；删除只改变衣橱及图片，穿搭引用不变，无跨存储键批量改写。穿搭默认画布使用最新展示图，显式模特预览和载入使用当前身材及衣物最新图片。

## 自由搭配画布（2026-10-13）

`OutfitService.createFree` 接收独立选衣草稿及选填名称，非空沿用名称校验，空白生成唯一日期标签。衣橱保存区内嵌输入框，无名称弹窗；成功清空名称，失败保留。可先打开紧凑画布。`Outfit.board` 为每件引用保存 0–100 方形坐标、缩放/旋转/叠放顺序，与人体 cm 参数分开；旧记录补默认位置，版号仍为 1。`saveBoard` 按 revision 只写排列，模特换衣保留仍在的画布位置并补新位置。

`rendering/outfit-board` 使用原展示图和透明内容边界，无人体变形，绘制/命中共享位置和层序；`components/outfit-board` 管理独立缓存、坏图占位与异步保护，复用手势控制器。单指默认滚屏，长按拖动并置顶，双指缩放旋转；调整期间禁滚，松手恢复。详情默认可编辑画布，身材只在点击模特页签时读取；未保存排列跨页面显示保留、离开警告、进入试衣先保存。回收站只读。

## 当前实现边界

新增穿搭日历使用独立 `smart-wardrobe.calendar.v1` 快照，按本地 `YYYY-MM-DD` 保存当天多套穿搭与注意事项，每日 revision 拦截过期写入。月历计算使用 UTC 中午进行纯日期运算，“今天”由设备本地年月日取得，避免 ISO 时区偏移。日期存档保留来源 ID、当时名称/衣物名/图层/变换，并复制展示照片到专用 `calendar_*` 文件；不复制身材或改写普通穿搭。

添加多套先准备照片，再一次写入日期记录；复制/写入失败回滚新副本。移除当天一套仅清理不再被日历引用的专用副本，原衣物照片和穿搭不动；空记录保留 revision 以拦截旧页面。图片清理为尽力执行，存储/文件容量错误保留用户输入并提示。页面负责月历、多选、备注保存保护与降级显示，业务和文件读写分别在服务/Repository 中。

已实现衣物管理、身材设置、参数化人体、衣物试穿和穿搭管理。没有已保存身材时使用明确标识的示例，示例不会自动持久化。已保存穿搭持久化；未保存修改仍驻留内存。微信原生交互仍待验证。

## 立体白模固定正面（2026-10-13）

开发时用 `mannequin-mesh` / `mannequin-raster` 生成三维白模投影，并由 scripts/generate-mannequin-assets.mjs 保存本地九格图集。运行时 `mannequin-atlas` 加载、`mannequin-warp` 按身材锚点/围度适配、`mannequin-surface` 缓存纹理；同身材换衣与手势复用。已取消运行时重型三维软件光栅化，模拟器曾发生超时。离屏失败直接适配图集，资源缺失降级曲线。基础衣裤按实际加载图层替换，不进入业务记录；前景只重画手颈，不提供转身。
