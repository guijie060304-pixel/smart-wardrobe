# 决策记录

## 2026-10-10：原生小程序与渐进式开发

沿用引用聊天中确定的原生 TypeScript/WXML/WXSS、Canvas 2D、本地存储方案。先建立可运行框架和稳定的数据边界，再逐阶段实现业务。现有 `project.config.json` 的 AppID 保留。

## 2026-10-10：第一阶段只建基础界面

四个导航页提供明确的空状态和后续阶段说明，不假装衣橱或试衣功能已可用。主题样式集中在全局 WXSS，业务字段集中在模型类型中。

## 2026-10-10：当前采用两级分类

用户明确暂不需要第三级，衣物分类使用“大类→具体品类”。版型等差异放在属性和标签中。

## 2026-10-10：身材输入与绘制分离

用户确认身高保持 150–200cm，体重和胸腰臀只检查有限正数，暂不设上限。保存原始数值；示意轮廓推算时限制比例以避免极端输入溢出或失去可视性。比例保护不作为输入上限。

人体路径、画布适配和绘制分别维护；X/Y 共用同一比例。未设置身材时显示明确标识的示例且不自动保存，表单初始参数为空。

## 2026-10-10：第四阶段试衣边界

支持上装、下装、外套及独立连体装；鞋履、配饰和整套套装暂不参与试穿。连体装与上装/下装双向互斥，外套可保留。同层选择替换已有衣物，重复选择保留原调整。

试衣会话使用内存草稿，切页保留，正式保存穿搭留到第五阶段。衣物和身材记录不因试衣操作而改变。优先使用试衣贴图，失败则回退展示照片并明确提示；普通背景不自动抠除。调整围绕图片中心，缩放为等比例。

## 2026-10-10：穿搭保存、回收站及缺失引用

用户确认删除衣物后保留穿搭并标记缺失，允许查看和替换。保存穿搭只引用衣物 ID、图层和逻辑调整参数；预览使用当前身材和衣物最新图片。不可用引用在编辑草稿中原样保留，明确替换/移除后才改变，不复制已删除图片。

穿搭删除使用回收站标记，可恢复；恢复穿搭不会恢复衣物。版本号用于拦截过期页面的保存/改名/删除/恢复；另存创建独立记录。未保存修改只驻留内存，载入其他穿搭或新建覆盖前确认。
